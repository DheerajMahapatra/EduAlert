# EduAlert: Early Identification of At-Risk Students Using Data Mining

An early-warning system that uses **earlier-period** academic, attendance, assessment and engagement data to flag students at **Low / Medium / High** academic risk *before* final exams, explains **why** each student was flagged, and suggests **support actions**.

> **Data note:** the dataset is **synthetic** (generated by `src/data_generation.py`). It is *not* real student data. Retrain on real, consented, anonymised institutional data before any real use.

## Quick start

```bash
pip install -r requirements.txt
python run_pipeline.py            # generate data -> clean -> EDA -> train -> cluster -> rules -> PDF report
streamlit run app/app.py          # open the dashboard
pytest -q tests                   # sanity tests
```

Optional: `pip install mlflow && python run_pipeline.py --mlflow` logs every model to MLflow (`mlflow ui`). Docker: `docker build -t edualert . && docker run -p 8501:8501 edualert`.

## How it works

```
Student data -> Cleaning -> Feature engineering -> EDA -> Data mining (Classification + Clustering + Association rules)
             -> Risk prediction (Low / Medium / High) -> Risk explanation -> Intervention suggestions -> Dashboard
```

| Component | File | What it does |
|---|---|---|
| Data generation | `src/data_generation.py` | 6,000 synthetic students with realistic quality issues (missing values, duplicates, impossible values) |
| Preprocessing | `src/data_preprocessing.py` | Dedupe, null invalid values, median/mode imputation, outlier capping |
| Feature engineering | `src/feature_engineering.py` | `Assessment_Avg`, `Attendance_Status`, `Engagement_Score`, `Academic_Performance_Index` |
| EDA | `src/eda.py` | The 4 spec questions: attendance, previous GPA, missed assignments, feature importance |
| Classification | `src/train.py` | Logistic Regression (baseline), Decision Tree, **Random Forest (primary, tuned)**, XGBoost |
| Clustering | `src/clustering.py` | K-Means (k=3) student groups + elbow/silhouette plot |
| Association rules | `src/association.py` | Apriori: which warning-sign combinations co-occur with High risk |
| Explanation + interventions | `src/utils.py`, `src/predict.py` | Rule-based risk factors and support suggestions |
| Dashboard | `app/app.py` | Dashboard, single-student prediction, batch CSV prediction, insights, model performance |
| Report | `src/make_report.py` | `reports/model_report.pdf` |

## Avoiding target leakage

`Risk_Level` is derived from a **later outcome** (`Final_Score`: High < 50, Medium 50-65, Low >= 65). `Final_Score` is **never** a model feature (asserted in `train.py` and covered by a test). Predictors only describe the earlier period.

## Results (held-out 20% test set, 1,200 students)

| Model | Accuracy | F1 (macro) | High-risk precision | High-risk recall | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression (baseline) | 0.756 | 0.734 | 0.672 | **0.810** | 0.908 |
| Decision Tree | 0.735 | 0.717 | 0.672 | 0.761 | 0.891 |
| **Random Forest (primary)** | **0.765** | 0.742 | 0.735 | 0.732 | **0.911** |
| XGBoost | 0.760 | 0.742 | 0.736 | 0.746 | 0.906 |

Honest reading of these numbers:

* Accuracy is about 76% on this noisy synthetic problem. Do not expect the same on real data.
* For an early-warning system the costly mistake is a truly High-risk student predicted Low, so **High-risk recall** matters most. The baseline Logistic Regression actually has the best High-risk recall; Random Forest has better precision. Lowering the decision threshold for the High class is the practical way to trade precision for recall.
* Top Random Forest drivers: Academic Performance Index, Assessment Avg, Previous GPA, Engagement Score.
* K-Means groups line up with risk: the "High attendance + high marks" cluster is 97% Low risk; the "Struggling & disengaged" cluster is 54% High risk.
* Strongest association rule: low assessment + low attendance + low previous GPA -> High risk (confidence about 96%, lift about 5.6).

The dashboard's cohort risk uses **out-of-fold** predictions (5-fold), so it never shows in-sample, over-optimistic scores.

## Dataset dictionary

`Student_ID, Age, Gender, Department, Semester, Previous_GPA, Attendance_Percentage, Assignment_Avg, Quiz_Avg, Midterm_Score, Practical_Score, Study_Hours, Classes_Missed, Assignments_Missed (of 10), Late_Submissions, Participation_Score, Previous_Backlogs` (predictors) + `Final_Score` (later outcome, not a predictor) + `Risk_Level` (target).

## Using your own data

Replace `dataset/students_raw.csv` with your file (same columns, including a later-outcome column used to derive `Risk_Level`), skip `data_generation`, and run `data_preprocessing`, `train`, etc. Check for group-level bias (gender, department) before deployment, and treat outputs as support suggestions reviewed by faculty, not judgements of a student's ability.
